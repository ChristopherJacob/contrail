# Contrail Core Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build sub-project 1 of Contrail: HAL, strip renderer, SDL desktop sim, settings, providers, flight model, and a core demo screen running on the CYD2USB.

**Architecture:** `lib/core` is pure C++17 (plus header-only ArduinoJson) and owns all logic and all pixel work. It draws into 240×32 RGB565 strip buffers through its own `Canvas`, so the renderer, fonts and goldens behave identically on every target. Thin HALs push finished strips to hardware: LovyanGFX on ESP32 (ILI9341 + XPT2046), raw SDL2 on desktop. Networking goes through `IHttp`, which streams bytes into ArduinoJson parsers.

**Tech Stack:** PlatformIO 6.2, espressif32 6.9 (Arduino 2.0.x), LovyanGFX 1.2.x (ESP32 only), ArduinoJson 7, WiFiManager (tzapu), SDL2 + libcurl (desktop), Unity (tests), Python + Pillow (font and asset generators), Inter font (OFL).

**Deviation from the writing-plans template (agreed with the user, who asked for autonomous execution):** tasks pin exact files, public interfaces, test cases and commands. Implementation bodies are written during execution rather than duplicated here, because this plan is executed inline by its author.

## Decisions taken while planning (refining the spec)

- Envs are `cyd2usb`, `cyd_microusb`, `sim` (SDL desktop app) and `test` (native Unity, no SDL). The spec's single `native` env is split into `sim` and `test`.
- Core rasterises everything itself. LovyanGFX is used only as the ESP32 panel and touch driver. SDL2 is used directly on desktop.
- Fonts are Inter, pre-rendered by `tools/gen_font.py` into 4-bit alpha glyph atlases (`lib/core/gfx/fonts/*.h`).
- Golden images are binary PPM files in `test/golden/`, regenerated with `UPDATE_GOLDEN=1`.
- Community host order is adsb.lol → adsb.fi v3 → airplanes.live. airplanes.live returned 403 to scripted requests during planning, so it's last. The device sends a `Contrail/<version>` User-Agent.
- TLS on ESP32 uses `WiFiClientSecure::setCACert` with an embedded multi-root PEM generated by `tools/gen_ca_bundle.py` from the system CA store. The roots are ISRG X1/X2, GTS R1–R4, DigiCert Global G2/G3, DigiCert Global Root CA, Amazon Root CA 1–4, USERTrust RSA/ECC and GlobalSign R3/R6.
- HTTP on ESP32 uses HTTP/1.0 (`useHTTP10(true)`) so ArduinoJson can stream the body without chunked decoding.

### Task 2: Colour, Canvas, dithered gradients

**Interfaces (`gfx/Color.h`, `gfx/Canvas.h`, `gfx/Dither.h`):**
```cpp
struct Rgb { uint8_t r,g,b; };
constexpr uint16_t rgb565(uint8_t r,uint8_t g,uint8_t b);
Rgb unpack565(uint16_t c);
Rgb lerp(Rgb a, Rgb b, float t);
uint16_t blend565(uint16_t dst, Rgb src, uint8_t alpha);   // alpha 0..255
uint16_t dither565(Rgb c, int x, int y);                   // 4x4 Bayer before truncation
class Canvas {                                             // window onto a global 240x320 space
 public:
  Canvas(uint16_t* buf, int width, int bandY, int bandH);  // buffer covers rows [bandY, bandY+bandH)
  int width() const; int bandY() const; int bandH() const;
  void setClip(Rect r); void resetClip(); Rect clip() const;    // global coords
  void pixel(int x,int y,uint16_t c);
  void blendPixel(int x,int y,Rgb c,uint8_t a);
  void fill(Rect r,uint16_t c);
  void fillBlend(Rect r,Rgb c,uint8_t a);
  void vGradient(Rect r, const Rgb* stops, const float* pos, int n);   // dithered
  void radialGlow(float cx,float cy,float radius,Rgb c,uint8_t peakAlpha); // quadratic falloff
  uint16_t* buffer(); uint16_t get(int x,int y) const;
};
struct Rect { int x,y,w,h; bool intersects(const Rect&) const; Rect intersect(const Rect&) const; bool empty() const; };
```
- [ ] Tests (`test/test_gfx_canvas`):
  - `rgb565(255,0,0)==0xF800`, `rgb565(0,255,0)==0x07E0`.
  - A pixel outside the band is ignored and the buffer is unchanged.
  - Fill clipped to the band writes only intersecting rows.
  - `blend565` at alpha 0 leaves dst unchanged and at alpha 255 equals the src colour.
  - A dithered gradient from (0,0,0) to (0,0,40) over 32 rows gives mean blue per row that increases monotonically, with at least 2 distinct values inside a 4×4 cell. This is the anti-banding check.
  - `radialGlow` gives centre pixel brightness > edge brightness, and pixels beyond the radius are unchanged.
- [ ] Implement, run `pio test -e test -f test_gfx_canvas`, commit.

### Task 3: Anti-aliased raster primitives

**`gfx/Raster.h`:** free functions on `Canvas&`:

### Task 10: readsb parser (community + local)

**`providers/ReadsbParser.h`:** `ParseResult parseReadsb(IByteSource& src, AircraftStore& store, uint32_t nowMs, Source source);` accepts `ac` or `aircraft` arrays. It maps `hex` (strips a leading `~`, which marks non-ICAO addresses and gets bit 24 set), `flight` (trimmed), `r`, `t`, `lat/lon` (falls back to `lastPosition` if present), `alt_baro` (number, or `"ground"` → flag), `gs`, `track` (falls back to `true_heading`), `baro_rate` (falls back to `geom_rate`), `squawk`, `emergency != "none"` or squawk 7500/7600/7700 → AC_EMERGENCY, `dbFlags & 1` → AC_MILITARY, `category` ("A3" → 0xA3), and `seen` sets the lastSeen offset. It uses an ArduinoJson filter.
- [ ] Tests with the recorded fixtures `adsblol_point.json` and `adsbfi_v3.json`: count == the number of entries with positions within radius (computed in the test from the fixture); hex `ae6827` has the military flag set; a synthetic `aircraft.json` (local receiver format, with an entry of `"alt_baro":"ground"` and squawk 7700) sets the ground and emergency flags; malformed JSON returns `ok=false` and leaves the store unchanged; an empty array is ok with 0.
